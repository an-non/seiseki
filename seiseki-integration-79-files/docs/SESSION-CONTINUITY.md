# セッション継続性・復元手順

- 文書版: 1.0
- 制定日: 2026-07-15
- 対象: 本ワークスペースで利用するCodexセッション

## 1. 目的

VS Code上のスレッド表示、ログイン状態、ネットワーク接続またはプロジェクト表示が失われても、次のセッションが作業状態・会話設計・判断経緯へ到達できるようにする。

完全に同一の将来応答は保証しない。モデル、システム指示、サンプリング、提供機能が変化すれば表現や判断候補は変わりうる。本対策は、差異をなくすのではなく、根拠となる記録と継続すべき意味を固定し、差異を検出・説明可能にする。

## 2. 三層構成

### 原記録層

- 原本: `%CODEX_HOME%/sessions/YYYY/MM/DD/rollout-*.jsonl`。`CODEX_HOME`未設定時はユーザーホームの`.codex`を使う。
- 保全先: ワークスペース直下の`session-archive/continuity/vault/`。
- ライブガードは10秒ごとにプロジェクト関連セッションの増分だけを追記する。
- 原本の短縮、既存ミラーとの不一致または世代変更を検出した場合、既存記録を変更せず新しい世代を作る。
- `auth.json`、Cookie、トークン、`.sandbox-secrets`は保全対象外。

### 意味層

- 会話形式: `docs/CONVERSATION-IF.md`。
- 安全・権限: `AGENTS.md`と`docs/AI-OPERATIONS.md`。
- 技術状態: `HANDOFF.md`。
- 私的な継続アンカー: `session-archive/continuity/anchors/`。Git対象外とし、外部送信しない。
- 各チェックポイントの`RESTORE-CAPSULE.md`には、復元順序と直近の可視会話を保存する。

### 起動層

- ワークスペース直下の`AGENTS.md`が、新規セッションへ復元順序を指示する。
- `.vscode/tasks.json`が手動ライブガード、手動チェックポイント、完全性検証を提供する。
- ライブガードはフォルダー起動時に自動開始しない。利用者がそのターンで明示した場合だけ起動する。
- ライブガードは開始から最大2時間で最終同期後に自己停止する。

## 3. 復元順序

1. ワークスペース直下とプロジェクト直下の`AGENTS.md`を読む。
2. `docs/CONVERSATION-IF.md`を読む。
3. `docs/AI-OPERATIONS.md`を読む。
4. 本書を読む。
5. `HANDOFF.md`を読む。
6. 最新チェックポイントの`RESTORE-CAPSULE.md`を読む。
7. `session-archive/continuity/anchors/`の最新アンカーを読む。
8. `node session-archive/continuity/verify.mjs`で完全性を検証する。
9. 曖昧な事項だけ、可読会話録または`raw/`の原イベントで確認する。
10. 復元できた事項、未確認事項、前回との差異を利用者へ報告する。

生ログを回答へ大量に再掲しない。認証情報や無関係な別セッションを読み込まない。

## 4. チェックポイント

重要な判断、機能変更、会話規則変更、長時間作業の区切り、セッション終了前に新しいチェックポイントを作る。

```text
node session-archive/continuity/checkpoint.mjs --reason manual
node session-archive/continuity/verify.mjs
```

チェックポイントは時刻別の新規ディレクトリとして作成し、過去分を上書きしない。書き込み中のJSONLは、取得開始時点の長さまでを一貫した記録として保存し、取得中に増えた分は次回のミラーまたはチェックポイントで回収する。

### 日跨ぎの再試行

`node session-archive/continuity/daily-retry.mjs` は、現在の日本日付について一度だけ保全状態を確認する。検証済みcheckpointがあれば何もしない。未作成でmain rolloutが存在すればcheckpoint作成と検証を行い、作業・チャットが無ければ`no-workspace-session`を記録する。各子処理は30秒で打ち切り、guard・server・watcherは起動しない。

この再試行は次回セッション開始時に実行できる。VS Codeフォルダー起動やOSログオン時の常駐実行、Windowsタスクスケジューラへの登録は既定で行わない。無人の日跨ぎ実行が必要な場合は、対象パス、保持期間、停止条件、認証範囲を示した別個の明示承認が必要になる。

## 5. 障害別の扱い

- **ネットワーク切断**: ライブ保全はローカル処理のため継続する。進行中の外部応答自体は回収できない場合がある。
- **VS Code終了・プロジェクト閉鎖**: ガードは停止しうるが、終了直前までのミラーと原本は残る。次回は自動再開せず、利用者の明示指示後に差分を回収する。
- **ログアウト**: プロセスは停止する。Windowsユーザープロファイルが保持される限り原本と保全先は残るが、削除されない保証はしない。
- **セッションUI消失**: 最新カプセル、可読会話録、原イベントから再構築する。
- **原本の短縮・変更**: 既存ミラーを保持し、新規世代として記録する。事故の可能性を報告する。
- **ハッシュ不一致**: 復元に使用せず、書き込みを止め、原本・複製・監査ログを保全して重大事故として報告する。

## 6. 保護できない範囲

現状の原本と保全先は同じWindowsユーザー・同じドライブにある。ディスク故障、ユーザープロファイル全削除、マルウェア、管理者権限による削除、ワークスペースと`.codex`の同時消失には耐えない。これらへ備えるには、別媒体または暗号化された別保管先が必要であり、保存先・暗号方式・保持期間を示した明示承認なしには実施しない。

`logs_2.sqlite`、`state_5.sqlite`、`memories_1.sqlite`などのライブDBは複数セッションとWALを含むため、既定ではコピーしない。必要な場合はSQLiteの整合したバックアップとして別途設計し、`auth.json`は含めない。
