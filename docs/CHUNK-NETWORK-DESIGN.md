# チャンクネットワーク設計

## 目的

既存の意見ネットワークは、同じトピックをまとめた集約ノードを表示する。別方式では、自由記述から抽出されたチャンク（意見）を1件ずつノードとして表示する。

## 分離境界

- 既存の `opinionNetwork`、`OpinionNetwork`、`tree-preview.html` は変更しない。
- 新しい変換は `core/chunk-network.js` の `chunkNetwork` に分離する。
- 将来のReact接続用描画器は `core/chunk-network.jsx` の `ChunkNetwork` とする。現在の `TreeView` からは呼び出さない。
- 確認用の固定サンプルは `local/chunk-network-preview.html` で表示する。

## 入力とノード

入力は `agg.opinions` のチャンク配列。ノードには本文、トピック、分類、対象、感情値、切実度、意欲、妥当性、事実性、接続数を保持する。件数引数を省略した場合は入力に存在する全チャンクを返す。

表示用のパラメータ重みは `切実度×0.50 + 意欲×0.30 + 妥当性×0.20` で算出する。さらに表示時だけ入力内の最小・最大で0〜1へ正規化し、以前の淡色から濃色へのグラデーションを再現する。色と中心距離は表示用の正規化値を使い、感情値は重み計算に含めない。感情値は詳細欄とツールチップで参照できる。

## リンク

リンクは「同じ属性だから」だけではなく、元のチャンク本文に戻って説明できることを優先する。`chunkContentTerms` は本文から漢字・カタカナ・英数字の語と2文字単位の語片を抽出し、共通語を `contentTerms` としてノードに保持する。

2つのチャンクには、次の順で関係を加点する。

- 本文の共通語: 0.48〜0.68。共通語の数と本文内の占有率で変動する。同一本文は0.82。
- 同じトピック: 0.24。
- 同じ対象: 0.14。
- 同じ分類: 0.08。
- 同じ事実性: 0.04。

合計0.24以上をリンクとして描画する。感情値はリンク条件から外し、詳細欄だけで参照する。各リンクは `primary`、`relations`、`sharedTerms`、`reasons` を持ち、線の色は主根拠に対応する（本文=緑、トピック=青、対象=金、分類=赤）。

プレビューでは凡例に主条件・補助条件を明示し、チャンク選択時に相手の本文と「本文の共通語: 税制」のような根拠を一覧表示する。これにより、線を見ただけでは判別しにくいリンクの定義を、個別のチャンク記述へ遡って確認できる。

## 配置と視認性

政治ラベルを中心の基準とし、重み1に近いチャンクほど小さな中心Gapへ、重み0に近いチャンクほど外周へ置く。高重み側は非線形に距離を縮め、中心付近へ密集させる。角度と半径には小さな決定的ランダムを加えるため、近接や軽い重なりが起こりうる。専用プレビューは既存の意見ネットワークと同じ中心放射を基礎に、ノードとリンクへ微細なドリフトだけを加える。本文は短縮ラベルを図中に表示し、完全なチャンクはホバーまたは選択時の詳細欄で確認する。既存の「上限なし」方針に合わせ、モデル側では件数を固定しない。

## 現時点のデータ境界

現在の集計オブジェクトは `agg.opinions` に直近120件のチャンクを保持している。この別方式は、その配列にある全件を表示する。過去分を含む完全な蓄積を扱う場合は、既存表示用の配列を変更せず、別のチャンクアーカイブを入力にする。
